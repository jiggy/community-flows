# Evidence and limitations

Status: provisional source package; not published, not an authorization service.
Initial implementation and controlled tests derive from Jig's software-factory
router at revision `846ad0f0e2eb5d96d63ff9b6099fcdbb3a340afe` (MPL-2.0).
Its example remains self-contained and does not depend on this collection.

`test/route.test.ts` controls Agent replies to check input bounds, unrelated
candidate sets, exact membership, abstention, malformed results, cancellation
and honest refusal. It does not establish applicability judgment, injection
resistance, host containment or live model reliability. Packed consumers check
artifact reuse separately from host execution.

Earlier live source comparisons include unfavorable routing outcomes and no
demonstrated advantage over explicit selection. They concern the original source
applications, not qualification of this archive. Prefer an explicit choice when
known. Do not claim semantic superiority, reliable routing or production maturity
from these tests. Fresh installed consumer evidence must name its artifacts and
limitations; it does not confer privileged collection trust.

Only the Agent collaborator is required. Candidate descriptions are reviewed
application data but can still influence model judgment. Returned IDs grant no
ability to execute, discover or install anything. The caller owns its exact map,
result validation, further checks and consequences. One call, no retry/fallback.
