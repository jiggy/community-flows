Flow at revision `846ad0f0e2eb5d96d63ff9b6099fcdbb3a340afe` (MPL-2.0).
The collection uses standard Node hashing with the same canonical digest format.
The originating example remains independent and unchanged by this extraction.

`test/repair.test.ts` uses controlled Agent replies and synthetic collected
command records. It checks two unrelated inputs, exact edit bounds, baseline
reproduction, proposal budgets, immutable acceptance, candidate identity,
truncation, uncertainty and cancellation. It neither executes candidate commands
nor proves model quality or host containment. Package-adoption tests separately
install complete archives outside the collection; they establish artifact reuse,
not admitted host execution.

The originating Jig application has recorded real repairs and unsuccessful runs.
Those results concern its own artifacts and selected inputs; they do not qualify
this new package or establish reliable repairs, comparative superiority, another
host's support, or production readiness. No live model campaign is part of this
collection's initial checks. A fresh installed consumer assessment is a separate
qualification; retained records must identify artifacts and any assistance.

from collection revision `4018b18`. Jig's candidate revision was `713a1bfb`.

It qualifies ordinary composition and finite acceptance, not repair intelligence,
